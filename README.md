# 记忆飞船 V7

一个面向个人学习场景的单词记录、复习与 AI 辅助学习应用。它把“录入新词、安排复习、标记难词、生成解析、整理历史记录”放在同一个系统里，适合长期积累自己的英语 / 日语词库。

## 功能介绍

### 1. 新词录入

- 手动录入单词、例句、手动释义和日期
- 录入后优先显示本地词典结果，再异步补充 AI 解析
- 自动记录最近 5 次手动录入结果，便于快速回看
- 词典读音和最简释义会写回数据库，刷新后仍可保留
- 支持英语 / 日语本地词典结果优先展示，不依赖浏览器直连外部词典

### 2. 复习系统

- 常规复习队列：按日期和阶段进入今日任务
- 当天巩固机制：
  - `忘记` 会退回第 0 周期，并要求当天重复达标
  - `模糊` 不升级周期，并要求当天重复达标
- 更随机的错题重现逻辑，避免固定 3-4 个后立刻再次出现
- `撤销上一步` 支持恢复复习进度和队列状态
- 电脑网页端支持复习快捷键，默认：
  - `A` 忘记
  - `S` 模糊
  - `D` 记得
- 可在设置页自定义复习快捷键
- 可在设置页控制“翻转前是否显示例句”
- 翻转后的答案面始终显示例句，方便继续对照

### 3. 重点巩固

- 自动统计每个词的 `忘记 / 模糊` 次数
- 达到阈值后自动迁移到“重点巩固”板块
- 重点巩固与常规复习共用同一套评分和调度逻辑
- 连续稳定表现后可自动退出重点巩固，避免永久堆积难词

### 4. 荣誉殿堂

- 已掌握词条可进入荣誉殿堂
- 支持从荣誉殿堂重新学习，把词重新放回复习体系

### 5. 词典与 AI 辅助

- 英语和日语都支持本地 SQLite 词典
- 词典查询优先返回基础读音、简短释义、词性
- AI 解析通过服务端代理请求第三方模型，避免浏览器直连模型接口
- 支持多家 AI provider 预设与服务端保存 API Key

### 6. 批量学习工具

- 文章智能解析：从文章中抽取重点词汇和表达后批量加入词库
- 写作进阶与润色：AI 润色文本，并把更地道的表达批量收藏
- Excel 导入：可把外部词表快速导入为词条

### 7. 数据查看与输出

- 词频统计
- 日期归档
- 日期归档中的单词卡片支持直接删除
- 列表页关键词搜索，可按单词、读音、释义、例句、AI 解析查询
- 听写纸生成与打印
- 听写纸支持三种题源：
  - 新词：按录入日期
  - 常规：按普通复习日期
  - 重点：按重点巩固日期
- Excel 导出

### 8. 账号与后台能力

- 用户登录与注册
- JWT 鉴权
- 服务端 SQLite 持久化
- 邀请码注册机制
- 管理员邀请码管理

## 项目特点

- 前后端一体：React + Vite 前端，Express + SQLite 后端
- 登录后数据按用户隔离
- AI Key 不直接在浏览器里调用第三方模型接口，而是通过服务端代理
- 保留了历史导入兼容接口，便于和其他项目联动
- 本地词典与网站运行时解耦，支持离线 `.mdx -> sqlite` 预处理

## 技术栈

- Frontend: React 19, Vite, Tailwind CSS, Lucide
- Backend: Express, JWT, bcryptjs
- Database: SQLite

## 快速开始

### 1. 安装依赖

```bash
npm install
```

### 2. 配置环境变量

复制 `.env.example` 为 `.env`，然后按需修改：

```bash
cp .env.example .env
```

最常用的变量有：

- `PORT`: 服务端端口，默认 `3001`
- `JWT_SECRET`: JWT 密钥
- `ADMIN_USERNAMES`: 管理员用户名，多个用逗号分隔
- `CORS_ORIGIN`: 允许的前端来源
- `DB_PATH`: SQLite 数据库文件路径
- `SERVE_STATIC`: 是否托管前端静态文件

### 3. 本地开发

前端开发模式：

```bash
npm run dev
```

构建前端：

```bash
npm run build
```

启动后端：

```bash
npm run start
```

默认访问地址：

- 前端 / 静态托管：`http://localhost:3001/`
- API：`http://localhost:3001/api/*`

## 重要说明

### 导入接口兼容

项目中保留了历史导入接口：

- `POST /api/data`

这个接口和其他项目有联动，**不要随意修改路径、入参结构和语义**。

### 安全与隐私

上传到 GitHub 前，请不要提交这些内容：

- `.env`
- `database.sqlite`
- `.well-known/`
- 部署目录副本
- 本地构建产物 `dist/`

仓库里的 `.gitignore` 已经默认忽略了这些文件，但如果你手动 `git add -f`，仍然可能把敏感内容提交上去。

### 单词加载与保存状态

- 已登录用户会先读取按账户 ID 隔离的 IndexedDB 快照，再在后台核对服务器数据。标有“本地待核对”的数量可能不是服务器最新值。首次在新浏览器登录时会同时请求到期复习记录及完整数据；先收到复习数据就能开始复习，其他依赖完整列表的页面继续等待全量请求。若当天到期记录占全部记录的大部分，首次加载提速可能有限。
- 单词与设置独立加载。设置请求超时或失败会显示错误和重试入口，不阻塞复习。完整单词请求有独立超时与退避重试；部分复习数据已就绪时，全量请求失败也不会把已取到的记录显示成空库。
- 本地缓存区分“部分复习记录”和“完整快照”；刷新后仍不会将局部数据误当作完整列表。浏览器本地存储不可用或升级被旧页面占用时，服务端数据仍会尝试加载，但复习操作会暂停并显示原因。`/api/data` 与 `/api/data/bootstrap` 的响应带有 `Server-Timing`，可结合线上 Network 面板区分服务端查询、序列化及网络传输耗时。
- 复习及词条更新先写入本地待同步队列，再更新界面。只有所有待同步操作收到服务器成功响应并完成本地确认后，顶部才显示“已保存到服务器”。断网时会保留待同步操作并退避重试；重新联网或页面恢复焦点也会重试。
- 服务端为每条记录维护 `revision` 与最近一次操作 ID。旧版本更新返回 409，不会静默覆盖其他设备的修改。发生冲突时，界面会保留本地操作，由用户明确选择采用本地或服务器版本。
- 退出登录会清空当前页面数据；当前账户的未同步操作仍保留在该浏览器，供下次登录同一账户时继续同步。不要在“待同步”状态清除浏览器网站数据。浏览器存储被清除、设备损坏或服务器自身数据丢失都不能由客户端队列恢复，生产环境仍需数据库备份。
- 首次部署此版本时先部署并启动服务端，再更新前端资源。服务端启动时对 `records` 表增加版本字段；部署前应备份 SQLite 数据库。旧前端没有提交版本字段，不能与新版更新接口混用。
- `npm test` 使用临时 SQLite 文件验证账户隔离、幂等更新、版本冲突，以及本地待同步操作恢复；不会使用项目的 `database.sqlite`。

### 邀请码与管理员

- 注册依赖服务端邀请码表，不再使用单个环境变量邀请码
- 管理员账号通过 `ADMIN_USERNAMES` 指定
- 管理员可在设置页内管理邀请码
- 系统冷启动且还没有任何邀请码时，命中管理员用户名的账号可免邀请码完成首次注册

## 本地词典说明

- 网站运行时默认读取：
  - 英语：`server/dictionaries/en/main.sqlite`
  - 日语：`server/dictionaries/ja/main.sqlite`
- `.mdx -> sqlite` 转换不在网站里执行，而是在本机离线执行
- 离线工具位于：
  - [server/dictionaries/convert_mdx_to_sqlite.py](./server/dictionaries/convert_mdx_to_sqlite.py)
  - [server/dictionaries/convert_mdx_to_sqlite_gui.py](./server/dictionaries/convert_mdx_to_sqlite_gui.py)
  - [server/dictionaries/launch_converter_gui.bat](./server/dictionaries/launch_converter_gui.bat)
  - [server/dictionaries/launch_converter_gui.command](./server/dictionaries/launch_converter_gui.command)
- 推荐流程：
  1. 准备 `.mdx` 源词典
  2. 用离线脚本、GUI、`.bat` 或 `.command` 转成 `main.sqlite`
  3. 网站运行时直接读取 SQLite，不在服务端动态解析 `.mdx`
